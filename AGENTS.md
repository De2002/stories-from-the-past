- Post images live in the private `post-images` bucket (public buckets are blocked by workspace policy); `posts.image_url` stores either a `/seed/...` public path or a storage path resolved to a signed URL by `PostImage`.
- Embeds from posts/comments to profiles must name the FK (`profiles!posts_user_id_fkey`) because likes/saves create ambiguous many-to-many paths.
- Admin reads and actions use authenticated server functions that verify the caller's persisted admin role before loading the privileged client; ordinary activity uses RLS-scoped browser queries.
- Moderation states are server-managed and separate from public profiles; suspended accounts cannot create content or engagement, while hidden posts remain readable by their author and admins.
- Profile photos use the private avatars bucket and store an owner-prefixed storage path; Avatar resolves signed links across all profile surfaces.
- Notification events are generated by database triggers, never client inserts; recipients may only read their own events and update the read flag.
